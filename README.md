# pdf2chunks

**Turn PDFs into JSONL chunks with page numbers and metadata, ready for RAG ingestion**

[![CI](https://github.com/GuiDobelin/pdf2chunks/actions/workflows/ci.yml/badge.svg)](https://github.com/GuiDobelin/pdf2chunks/actions/workflows/ci.yml)
![Python](https://img.shields.io/badge/python-3.11%2B-blue)
![License](https://img.shields.io/badge/license-MIT-green)

Text pulled straight out of a PDF is a poor input for retrieval. Every page repeats its running
header, footer and page number, words are hyphenated across line breaks, ligatures show up as odd
characters, and lines are hard-wrapped. If you split that text naively, chunks get diluted by
boilerplate, and you lose the page a citation should point to.

`pdf2chunks` extracts the text with [pypdf](https://github.com/py-pdf/pypdf) and cleans it. It
then packs paragraphs into size-bounded chunks, and every chunk records the pages it came from.
The output is one JSON object per line, ready to embed and index. It is a small CLI and library
with a single dependency.

What it does:

- **Removes headers, footers and page numbers.** It drops lines that repeat at the top or bottom
  of most pages (digits are ignored, so `Report · 3` matches `Report · 4`) and lines like
  `12`, `- 4 -` or `Page 3 of 10`.
- **Repairs text.** It joins words hyphenated across lines and across page breaks, but keeps
  hyphens in `COVID-19` or `Jean-Paul`. It also fixes ligatures (`ﬁ` → `fi`), soft hyphens
  and non-breaking spaces.
- **Reflows paragraphs.** Wrapped lines are merged into paragraphs, and headings and list items
  start new ones.
- **Chunks with page awareness.** Paragraphs are kept whole when they fit, and longer ones are
  split at sentence ends. Each chunk carries `page_start`/`page_end` and a stable id, and
  repeats whole trailing sentences of the previous chunk as overlap. A chunk never ends on a
  heading.
- **Handles real-world files.** It reads encrypted PDFs (the password comes from an environment
  variable), lets you select pages, processes whole folders, reports damaged files without
  stopping the batch, and warns about scanned PDFs that have no text layer.

```text
                  [--raw] [--password-env VAR] [--stats] [--version]

Turn PDFs into JSONL chunks with page numbers and metadata, ready for RAG ingestion. Writes one
JSON object per chunk.

positional arguments:
  PATH                  PDF files or folders (searched recursively for *.pdf); - reads standard
                        input

options:
  -h, --help            show this help message and exit
  -o OUTPUT, --output OUTPUT
                        write JSONL here (default: stdout)
  --max-chars MAX_CHARS
                        maximum characters per chunk (default: 1200)
  --overlap OVERLAP     characters of trailing sentences repeated in the next chunk (default: 150)
  --pages PAGES         only these 1-based pages, e.g. 1-3,7 (default: all)
  --raw                 skip cleaning (keep headers, footers, page numbers and hyphenation)
  --password-env VAR    read the password for encrypted PDFs from this environment variable
  --stats               print pages, chunks and characters per file to stderr
  --version             show program's version number and exit
```

## Usage

### CLI

[`examples/handbook.pdf`](examples/handbook.pdf) is a two-page PDF with a running header, a
`Page N of 2` footer and words hyphenated at line ends. It is generated by
[`scripts/make_example.py`](scripts/make_example.py).

```text
$ pdf2chunks examples/handbook.pdf --max-chars 400 --overlap 80 | head -1 | python -m json.tool
{
    "id": "d332076a027ea162",
    "source": "examples/handbook.pdf",
    "index": 0,
    "page_start": 1,
    "page_end": 1,
    "chars": 310,
    "text": "1. On-call basics\n\nEvery service has a primary and a secondary on-call engineer. The primary acknowledges a page within five minutes and opens an incident channel; the secondary takes over if there is no acknowledgement after fifteen minutes. Handover happens every Monday at 10:00 and is recorded in the rota.",
    "metadata": {
        "title": "Engineering Handbook",
        "author": "Acme Platform Team",
        "page_count": 2
    }
}
```

The header and the footer are gone. The paragraph reads as prose, and the heading stays with
its section.

```bash
# a whole folder into one file, with a per-file summary on stderr
pdf2chunks docs/ -o chunks.jsonl --stats

# only some pages, and an encrypted PDF
read -rs PDF_PASSWORD && export PDF_PASSWORD
pdf2chunks contract.pdf --pages 1-3,7 --password-env PDF_PASSWORD

# from standard input, without any cleaning
curl -s https://example.com/paper.pdf | pdf2chunks - --raw
```

```text
$ pdf2chunks examples/handbook.pdf --max-chars 400 --overlap 80 --stats > /dev/null
examples/handbook.pdf: 2 pages of 2, 3 chunks, 876 characters
```

With `--pages`, a PDF that has only some of the selected pages yields those pages and a
warning, so a batch is not stopped by one short file. The exit status is 0 on success and 1 if
any input could not be read. The chunks of the other
files are still written. With `-o`, the file is written atomically, so an interrupted run never
leaves half a file behind.

### Python

```python
from pdf2chunks import pdf_to_chunks

for c in pdf_to_chunks("examples/handbook.pdf", max_chars=400, overlap=80):
    print(c.index, c.page_start, c.page_end, c.text.split("\n")[0])
```

```text
0 1 1 1. On-call basics
1 1 1 2. Severity levels
2 2 2 3. Postmortems
```

The steps are also available one by one, so you can swap any of them:

```python
from pdf2chunks import chunk_pages, clean_pages, read_pdf

doc = read_pdf("report.pdf", pages=range(1, 11))  # Document: pages, metadata, warnings
pages = clean_pages(doc.pages)  # Page(number, text) with clean paragraphs
chunks = chunk_pages(
    pages, max_chars=800, overlap=100, source="report.pdf", metadata={"collection": "finance"}
)
rows = [c.to_dict() for c in chunks]  # what the CLI writes, one per line
```

`read_pdf` accepts a path, `bytes` or a binary file object. It raises `PdfError` for damaged
or encrypted files.

### Output format

Each line holds one chunk:

| field | meaning |
|---|---|
| `id` | 16 hex characters, derived from the source, the position and the text; the same input always gives the same ids |
| `source` | the path as given (`<stdin>` for `-`) |
| `index` | 0-based position of the chunk in its document |
| `page_start`, `page_end` | 1-based pages the chunk's text comes from, overlap included |
| `chars` | length of `text` |
| `text` | paragraphs separated by blank lines |
| `metadata` | the PDF's `title`, `author`, `subject`, `keywords`, `creator`, `producer` and `created` when present, plus `page_count` |

## Limitations

- There is no OCR. Scanned PDFs without a text layer produce no chunks, and the CLI warns about
  them.
- Paragraph detection is a heuristic based on line length and punctuation. It works best on
  justified prose. Multi-column layouts and tables come out in pypdf's reading order.
- Header detection compares the pages being processed, so selecting one or two pages of a long
  document may keep its headers.

## Ecosystem

Part of a set of small tools around [citerag](https://github.com/GuiDobelin/citerag), a self-hostable
RAG API that answers questions about your documents with verifiable citations. `pdf2chunks`
produces the page-aware chunks that make those citations point to the right page.
